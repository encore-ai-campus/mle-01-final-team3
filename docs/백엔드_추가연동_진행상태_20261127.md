## 구현 완료

### 인증·세션·역할

- `POST /api/v1/auth/login` 호출을 추가했다.
  - 요청 필드: `email`, `password`, `loginType` (`STAFF` 또는 `ADMIN`)
  - `credentials: include`로 HttpOnly `adguard_session` 쿠키를 사용한다.
- 앱 시작 시 `GET /api/v1/me`로 세션을 확인한다.
- `POST /api/v1/auth/logout`의 204 응답을 처리하고 앱 사용자 상태를 제거한다.
- 서버 역할을 화면 권한 모델로 변환한다.
  - `MARKETING` → 마케팅 부서, reviewer
  - `LEGAL` → 법무 부서, reviewer
  - `ADMIN` → unknown 부서, admin
- 로그인 화면에서 이메일·비밀번호와 로그인 사용자 유형을 입력할 수 있다.
- 실제 사용자 이름·부서·관리자 권한을 앱 셸과 메뉴에 반영했다.
- 사이드바에 로그아웃을 연결했다.
- 계정 페이지의 내 정보 조회를 `GET /me`에, 비밀번호 변경을 `PATCH /me/password`에 연결했다.

### 공통 오류

백엔드 오류 응답의 다음 필드를 `ApiError` 최상위에도 보존한다.

- `code`
- `retryable`
- `requestId`
- `fieldErrors`

기존 `details` 원문도 함께 유지한다.

### 검토 실행 어댑터

`ApiProvider.reviewFlow`로 다음 REST 계약을 사용할 수 있다.

- `POST /attachments` multipart 업로드 (`file`, `purpose`)
- `POST /reviews` 검토 생성 및 `Location` 보존
- `GET /reviews/{reviewId}` 상세 조회
- `GET /review-runs/{runId}` 실행 상태 조회
- `POST /review-runs/{runId}/retry` 재시도
- `POST /reviews/{reviewId}/ra-runs` AI 추천
- `POST /reviews/{reviewId}/ra-runs/{runId}/recheck` 추천 재검토
- `POST /reviews/{reviewId}/ra-runs/{runId}/dismiss` 추천 기각

생성·재시도·추천·재검토 요청에는 `Idempotency-Key`를 사용하며, 실행 단계와 상태의 대문자 enum을 그대로 보존한다. 상세 보고서 필드는 Agent 계약이 확정될 때까지 원문 형태로 보존한다.

## 아직 연결하지 않은 항목

### 검토 목록

백엔드 답변 기준 목록 API가 아직 없다. 따라서 `/reviews` 화면에 임의의 경로를 연결하지 않았고, API 모드에서는 기존 `listReviews`가 `not-configured` 상태로 남는다.

필요한 백엔드 확정 사항:

- 목록 경로와 HTTP method
- 검색 필드와 query parameter 이름
- 상태·AI 판정·담당자·날짜 필터의 enum/형식
- 페이지네이션 방식 (`cursor` 또는 `page/pageSize`)
- 응답의 전체 건수와 다음 페이지 표기 방식

### Agent 실행 검증

백엔드 답변에 따르면 현재 Agent가 없어 검토 요청이 `AGENT_UNAVAILABLE`로 실패한다. 따라서 실제 Agent 성공 보고서 렌더링과 2초→4초→5초 폴링의 로컬 E2E는 아직 검증하지 못했다.

### 기존 화면 액션과 새 백엔드 액션의 차이

현재 `ReviewDetailPage`는 fixture용 이전 액션 이름을 사용한다. 백엔드의 새 `allowedActions`에는 `RETRY_RUN`, `RUN_RA`, `RECHECK_SUGGESTION`, `DISMISS_SUGGESTION` 등이 사용된다. 두 모델을 임의로 매핑하지 않았으며, 다음 단계에서 화면이 새 `allowedActions`를 직접 기준으로 버튼을 표시하도록 개편해야 한다.

또한 `CANCEL`, `END`, `PUBLISH`, `SEND_TO_LEGAL` API는 백엔드 미구현으로 확인되어 있다.
