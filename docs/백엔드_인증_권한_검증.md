# 백엔드 인증·권한 검증

담당: 엄가현 / 코드: `src/backend` / 기준: 백엔드 API 설계서 v5.0, ERD v0.4

## 권한 매트릭스

로그인 안 함 → 모든 API 401 `UNAUTHENTICATED`. 역할이 안 맞음 → 403 `FORBIDDEN`.

| 코드에서 쓰는 이름 (`app/core/deps.py`) | 허용 역할 | 쓰는 곳 (설계서 기준) |
| --- | --- | --- |
| `CurrentUser` | 로그인한 누구나 | 로그아웃, 내 정보, 비밀번호 변경 |
| `Marketer` | MARKETING | 검토 요청·조회, 첨부, AI 추천, 법무 검토 요청, 끝 처리, 재시도 |
| `Lawyer` | LEGAL | 법무 검토함, 검토 시작, 의견 전송 |
| `Admin` | ADMIN | 사용자 관리 (`/admin/users`) |
| `Staff` | MARKETING, LEGAL | 대시보드, 알림, 실행 상태 조회 |
| `verify_agent_token` | Agent (서비스 토큰) | Agent 완료 통지 |

작성자 본인만 가능한 동작(예: 법무 검토 요청)은 역할 검사 뒤에 각 API에서 따로 확인합니다.

## 검증 절차

`src/backend` 폴더에서 실행합니다. 테스트는 `adguard_test` DB를 자동으로 만들고, 빈 DB에 마이그레이션을 처음부터 적용한 뒤 돌기 때문에 마이그레이션 검증도 함께 됩니다.

```bash
uv run pytest tests -v       # 마지막 줄에 47 passed
uv run alembic check         # "No new upgrade operations detected" = 모델과 DB가 일치
```

| 테스트 파일 | 확인하는 것 |
| --- | --- |
| `tests/test_auth.py` | 로그인 성공(쿠키·10시간 세션·로그인 기록), 실패 4종(`USER_NOT_FOUND`·`INVALID_PASSWORD`·`ACCOUNT_INACTIVE`·`ADMIN_ROLE_REQUIRED`), 세션 없음·만료·로그아웃·비활성화 후 401, 임시 비밀번호 안내와 비밀번호 변경, CLI 첫 ADMIN |
| `tests/test_permissions.py` | 역할 3개 × 권한 5종 허용·거부, 로그인 안 하면 전부 401, 세션 강제 종료, Agent 서비스 토큰 |
| `tests/test_admin_users.py` | 관리자 API 6개: 목록·등록·수정·이관·삭제·활동 로그, 자기 자신·마지막 관리자 보호, 넘길 건 409, 중복 요청 방지 |
| `tests/test_cors.py` | 프론트 주소(`localhost:5173`)와 쿠키 허용, 다른 주소 차단 |

### Swagger로 직접 확인

1. `uv run python -m app.seed_dev` → `uv run uvicorn app.main:app --reload`
2. http://localhost:8000/docs 에서 `POST /api/v1/auth/login`
   `{"email": "admin@adguard.local", "password": "adguard1234", "loginType": "ADMIN"}`
3. `GET /api/v1/admin/users` → 200
4. `POST /api/v1/auth/logout` 후 같은 API → 401 `UNAUTHENTICATED`
5. `marketing@adguard.local`로 로그인 후 같은 API → 403 `FORBIDDEN`

## 테이블을 바꿀 때 (가현 담당)

1. `app/models.py`를 고친다.
2. `uv run alembic revision --autogenerate -m "바꾼 내용"`으로 새 마이그레이션 파일을 만든다.
3. 생성된 파일을 열어 의도한 변경만 들어갔는지 확인한다.
4. `uv run alembic upgrade head`로 적용한다.

이미 올린 마이그레이션 파일은 고치지 않고 항상 새 파일을 추가합니다.
