# 백엔드 인증·권한 검증

담당: 엄가현 / 코드: `src/backend` / 기준: 백엔드 API 설계서 v5.3, ERD v0.5

## 공통 오류 응답

모든 오류는 같은 모양입니다. (`app/core/errors.py`).

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "입력값을 확인해 주세요.",
    "retryable": false,
    "requestId": "req_3f2a9c1b7e",
    "fieldErrors": [{"field": "temporaryPassword", "code": "REQUIRED"}],
    "details": {"openReviews": 2, "inReviewSubmissions": 0}
  }
}
```

- `fieldErrors`: 입력 오류가 난 필드를 알 수 있습니다. 빈 값은 `REQUIRED`, 형식 오류는 `INVALID`. 없으면 `[]`로 표시됩니다.
- `details`: 추가 정보(건수 등)를 알 수 있습니다. 담을 정보가 있을 때만 표시됩니다.

| 상태 | code | 발생 조건 |
| --- | --- | --- |
| 400 | `INVALID_QUERY` / `INVALID_CURSOR` | 조회 조건 오류 / 잘못되거나 만료된 커서 |
| 401 | `UNAUTHENTICATED` | 세션 쿠키 없음·만료, Agent 서비스 토큰 불일치 |
| 401 | `USER_NOT_FOUND` / `INVALID_PASSWORD` | 존재하지 않는 계정(삭제된 사용자 포함) / 비밀번호 불일치 |
| 403 | `ACCOUNT_INACTIVE` / `ADMIN_ROLE_REQUIRED` | 비활성 계정 로그인 / 비관리자 계정으로 관리자 로그인 시도 |
| 403 | `FORBIDDEN` | 역할 권한 없음, 관리자 본인 계정 비활성화·삭제·역할 변경, 허용되지 않은 주소(Origin)에서 온 변경 요청 |
| 404 | `NOT_FOUND` | 대상 없음, 삭제된 사용자 대상 |
| 409 | `EMAIL_ALREADY_EXISTS` | 중복 이메일 등록 |
| 409 | `LAST_ADMIN` / `HANDOVER_REQUIRED` | 마지막 관리자 / 인계할 항목이 존재함 |
| 409 | `STATE_CONFLICT` | 이미 사용한 요청 키로 다른 내용의 요청 전송 |
| 422 | `VALIDATION_ERROR` | 입력 누락·형식 오류 |
| 422 | `INVALID_CURRENT_PASSWORD` / `PASSWORD_POLICY_VIOLATION` | 현재 비밀번호 불일치 / 비밀번호 정책 미충족(8자 이상, 영문·숫자 포함) |
| 500 | `INTERNAL_ERROR` | 서버 내부 오류 |

## 권한 매트릭스

인증이 필요한 API에 로그인 없이 접근하면 401 `UNAUTHENTICATED`를 반환합니다. 로그인했더라도 해당 API에 필요한 역할 권한이 없으면 403 `FORBIDDEN`을 반환합니다.

| 코드에서 사용하는 이름 (`app/core/deps.py`) | 허용 역할 | 적용 기능 |
| --- | --- | --- |
| `CurrentUser` | 역할에 관계없이 로그인한 사용자 | 로그아웃, 내 정보, 비밀번호 변경 |
| `Marketer` | 마케팅 담당자 (MARKETING) | 검토 요청·조회, 첨부, AI 추천, 법무 검토 요청, 완료 처리, 재시도 |
| `Lawyer` | 법무 담당자 (LEGAL) | 법무 검토함, 검토 시작, 의견 전송 |
| `Admin` | 관리자 (ADMIN) | 사용자 관리 (`/admin/users`) |
| `Staff` | 마케팅 담당자 또는 법무 담당자 (MARKETING, LEGAL) | 대시보드, 알림, 실행 상태 조회 |
| `verify_agent_token` | 유효한 서비스 토큰을 가진 Agent | Agent 완료 통지 |

일부 기능(법무 검토 요청 등)은 해당 역할을 가지고 있어도 작성자 본인만 실행할 수 있습니다. 각 API에서 역할 권한을 확인 후, 작성자 본인인지 추가로 확인합니다.

## 활동 로그 규칙

모든 활동 로그는 `log_activity` 함수(`app/core/activity.py`) 하나로 같은 형식으로 남깁니다.

| 칸 | 내용 |
| --- | --- |
| `userId` | 작업한 사람 |
| `operation` | 작업 종류 (아래 목록) |
| `targetLabel` | 대상. 검토 작업은 검토 제목(보고서 조회는 '{제목} 검토 보고서'), 사용자 관리 작업은 대상 userId, 로그인·로그아웃은 없음 |
| `occurredAt` | 작업 시각 |

- 작업 종류: `LOGIN`, `LOGOUT`, `REVIEW_REQUESTED`, `RA_RECHECK_REQUESTED`, `SUGGESTION_RECHECKED`, `SUGGESTION_DISMISSED`, `RUN_RETRIED`, `LEGAL_SENT`, `REPORT_VIEWED`, `LEGAL_OPINION_SENT`, `REVIEW_CLOSED`, `USER_CREATED`, `USER_UPDATED`, `WORK_HANDED_OVER`, `USER_DELETED`
- 사용자 관리 로그(`USER_*`, `WORK_HANDED_OVER`)는 이름·이메일 대신 userId를 남깁니다. 계정을 삭제한 뒤에도 다른 로그에 개인정보가 남지 않게 하기 위해서입니다.

### 로그에 남기지 않는 것

활동 로그와 서버 로그(오류 기록·접속 기록) 모두에 아래 값을 남기지 않습니다.

- 비밀번호 (입력값, 암호화한 값 모두)
- 세션 토큰 (쿠키 `adguard_session` 값)
- Agent 서비스 토큰
- 첨부 다운로드 주소의 서명(`sig`). 서버 접속 기록에서는 `***`로 가립니다 (`HideSignature`).
- 첨부 파일 저장 경로

## 보안 기준

| 항목 | 기준 |
| --- | --- |
| 로그인 쿠키 | `adguard_session`. HttpOnly(자바스크립트로 읽을 수 없음), SameSite=Lax, 로그인 후 8시간 고정. DB에는 토큰 원래 값이 아니라 SHA-256 값만 저장합니다. |
| 쿠키 Secure | 배포(HTTPS)에서는 `.env`에 `COOKIE_SECURE=true`를 설정해 HTTPS에서만 쿠키를 보내게 합니다. 로컬 개발은 `false`입니다. |
| CSRF | 토큰을 쓰지 않습니다. SameSite=Lax 쿠키, CORS 허용 주소 제한(`CORS_ORIGINS`), Origin 검사(`app/core/origin.py`)로 막습니다. Origin 검사는 허용 주소나 백엔드 자기 주소가 아닌 곳에서 온 POST·PATCH·DELETE를 403으로 거절합니다. GET 요청은 데이터를 바꾸지 않습니다. |
| 로그인 실패 제한 | 확장 기능으로 미뤘습니다. 현재는 없습니다. |
| Agent 토큰 | `.env`의 `AGENT_TOKEN`으로 관리합니다(`.env`는 git에 올리지 않음). 토큰을 바꾸는 동안에는 `AGENT_TOKEN_EXTRA`도 받습니다. 설정된 토큰이 없으면 Agent 요청을 모두 거절합니다. 로그에는 남기지 않습니다. |
| 첨부 업로드 | `.pdf`·`.xlsx`·`.docx` 확장자만 받습니다. 저장 파일 이름은 사용자가 보낸 이름이 아니라 서버가 만든 ID(예: `att_001.pdf`)라서 경로 조작(`../` 등)이 통하지 않습니다. MIME·파일 시그니처 검사는 검토 흐름 및 Agent 연동 담당이 추가할 예정입니다. |
| 첨부 다운로드 | Agent는 10분 동안만 쓸 수 있는 서명 주소(`/internal/v1/attachments/{id}?expires=..&sig=..`)로 내려받습니다. 서명은 서버 접속 기록에서 가립니다. |

## 검증 절차

`src/backend` 폴더에서 테스트를 실행합니다. 테스트 실행 시 `adguard_test` DB를 자동으로 생성하고, 시작할 때 모델 기준으로 테이블을 새로 만듭니다. 마이그레이션은 거치지 않으므로, 마이그레이션은 아래 '새 환경에서 재현'으로 따로 확인합니다.

```bash
uv run pytest tests -v       # 마지막 줄에 172 passed (검토 흐름 테스트 포함)
```

### 새 환경에서 재현 (마이그레이션 포함)

빈 DB에 마이그레이션을 처음부터 적용하고, 모델과 DB가 일치하는지 확인한 뒤 테스트를 실행합니다. PostgreSQL 설치와 `.env` 준비는 `src/backend/README.md`를 따릅니다.

```bash
createdb adguard_verify
export DATABASE_URL=postgresql+psycopg2://사용자:비밀번호@localhost:5432/adguard_verify
uv run alembic upgrade head   # 마이그레이션 2개 적용 (65c4403ed32d → 844f6c112613)
uv run alembic check          # "No new upgrade operations detected." = 모델과 DB가 일치
unset DATABASE_URL
uv run pytest tests -v        # 172 passed
dropdb adguard_verify
```

### 역할별 접근 권한

로그인한 사용자의 역할에 따라 아래와 같이 접근이 허용되거나 차단됩니다.

- **허용**: 요청 성공(200)
- **차단**: 권한 부족으로 접근 거부(403)
- 로그인하지 않은 경우: 아래 모든 권한 검사에서 인증 오류(401)

| 접근 조건 (코드 이름) | 관리자 (`ADMIN`) | 마케팅 (`MARKETING`) | 법무 (`LEGAL`) |
| --- | --- | --- | --- |
| 로그인한 사용자 (`CurrentUser`) | 허용 | 허용 | 허용 |
| 마케팅 담당자 (`Marketer`) | 차단 | 허용 | 차단 |
| 법무 담당자 (`Lawyer`) | 차단 | 차단 | 허용 |
| 관리자 (`Admin`) | 허용 | 차단 | 차단 |
| 마케팅·법무 담당자 (`Staff`) | 차단 | 허용 | 허용 |

관리자 역할이 모든 기능의 접근 권한을 포함하지는 않습니다.
마케팅·법무 전용 기능은 해당 역할을 가진 사용자만 접근할 수 있습니다.

## 데이터베이스 구조 변경 방법

1. `app/models.py`에서 모델을 수정합니다.
2. 다음 명령어로 마이그레이션 파일을 생성합니다.
   ```bash
   uv run alembic revision --autogenerate -m "변경 내용"
   ```
3. 생성된 파일에 의도한 변경만 포함되어 있는지 확인합니다.
4. 다음 명령어로 데이터베이스에 적용합니다.
   ```bash
   uv run alembic upgrade head
   ```

이미 공유하거나 배포한 마이그레이션 파일은 수정하지 않고, 새 마이그레이션 파일을 추가합니다.
