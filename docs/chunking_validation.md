# 청킹 결과 검증 및 인계 (2026-11-26)

## 판정

이전에 발견한 두 PDF의 바닥글 혼입과 3단 표 열 순서 오류를 **파싱 원본에서 수정하고 해당 문서의 청크를 재생성했다.** 레지스트리 453개 문서가 모두 통합 JSONL에 있으며, JSON 파싱·중복 ID·부모 참조·원본 줄 범위 검사를 통과했다. 두 문서 외 451개 문서의 청크 바이트는 이전 결과와 동일하다. 전체 OCR 문서의 육안 검수와 팀 샘플 합의는 별도 단계다.

## 이번 교정

- 원본 법령에 항이 없고 호가 조에 바로 달린 512개 청크 ID에서 가상의 `P001`을 제거했다. 부모는 실제 조 또는 호 ID로 연결했다.
- OCR 문서 29개의 청크를 원본 `pages[].lines` 순서로 다시 생성했다. 이전에 건너뛴 내용 있는 81페이지를 복구했고, 실제 텍스트가 거의 없는 페이지 36건만 빈 페이지로 기록했다.
- 레지스트리의 기능성원료 TXT 보고서 394개를 소제목·줄 경계 기준 3,448개 청크로 추가했다. 식품원료 JSONL 13,880레코드도 추가했다.
- 제목 중복으로 누락됐던 고시 OCR 3개와 법령 API 1개를 별도 문서 ID로 포함했다.
- 필드 이름을 본문으로 잘못 넣었던 고시 별표를 원본 별표 내용으로 교체했다. 고시 별표 3개에는 부모 표와 하위 줄·행 청크 84개를 연결했다.
- **이번 수정:** 제2021-89호 고시 PDF 4쪽의 반복 바닥글 4줄을 파싱 원본에서 제거했다. 판단 안내서 PDF의 3단 표 54쪽은 원본 PDF 좌표로 각 열을 위에서 아래로 다시 추출했다. 두 문서를 재청킹해 통합 결과에 교체했다.

## 배포 전 확인할 사항

1. 이번 두 PDF의 오류는 수정·검증했다. 나머지 OCR 페이지 전체를 사람이 육안으로 검수한 것은 아니므로 전 문서의 OCR 의미 품질을 무조건 보증할 수는 없다.
2. 수정된 두 문서의 청크 ID와 분할 경계가 바뀌었다. 기존 ID를 사용한 온톨로지·Neo4j·RAG 인덱스는 새 파일 기준으로 다시 적재해야 한다.
3. 대표 50건의 파싱 원본 대조는 통과했지만, 브리프의 **팀 샘플 합의**는 별도 확인이 필요하다.
4. 대용량 파일의 실제 Drive 위치를 매니페스트 `storage_uri`에 입력하고, 업로드본의 크기와 SHA-256을 다시 확인해야 한다.

PDF 원본 재파싱은 `scripts/reparse_affected_pdfs.py`, 통합 재생성은 `scripts/reconcile_chunking_release.py`다. 전수 원본 범위 검사는 `scripts/verify_chunking_release.py`, PDF 대조는 `scripts/verify_reparsed_pdfs.py`, 샘플 대조는 `scripts/audit_chunking_samples.py`다. 통합 재생성에는 이전 전달본 `structured_chunks-001 (1).jsonl`과 당시 스키마·품질 로그가 입력으로 필요하다.
