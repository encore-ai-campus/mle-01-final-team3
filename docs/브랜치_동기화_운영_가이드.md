# 브랜치·PR 동기화 운영 가이드

이 저장소는 `main`과 feature 작업을 서로 다른 worktree에서 관리한다. 한
worktree에서 브랜치를 번갈아 checkout하지 않는 것이 핵심 규칙이다.

## 권장 폴더 구조

```text
최종프로젝트/
├─ mle-01-final-team3/       # 기존 feature 작업 worktree
├─ mle-01-final-team3-main/  # main 전용 worktree
└─ mle-01-final-team3-<name>/# 새 feature 전용 worktree
```

`main` worktree는 최신 기준점만 유지하고, 실제 변경은 feature worktree에서만
수행한다.

## 새 작업 시작

PowerShell에서 `main` worktree를 최신화한 뒤 새 브랜치를 만든다.

```powershell
$main = "C:\Users\Playdata\Desktop\김동석\최종프로젝트\mle-01-final-team3-main"
$feature = "C:\Users\Playdata\Desktop\김동석\최종프로젝트\mle-01-final-team3-<작업명>"
$oldLfsSkip = $env:GIT_LFS_SKIP_SMUDGE
try {
    $env:GIT_LFS_SKIP_SMUDGE = "1"
    git -C $main fetch origin --prune
    if ($LASTEXITCODE -ne 0) { throw "origin fetch failed" }
    git -C $main pull --ff-only
    if ($LASTEXITCODE -ne 0) { throw "main pull failed" }
    git -C $main worktree add -b "feat/<작업명>" $feature origin/main
    if ($LASTEXITCODE -ne 0) { throw "feature worktree creation failed" }
}
finally {
    if ($null -eq $oldLfsSkip) { Remove-Item Env:GIT_LFS_SKIP_SMUDGE -ErrorAction SilentlyContinue }
    else { $env:GIT_LFS_SKIP_SMUDGE = $oldLfsSkip }
}
```

작업 중에는 `$feature` 경로에서만 파일을 수정하고 commit/push한다.

## PR 전 점검

```powershell
git -C $feature status --short --branch
git -C $feature diff --check origin/main...HEAD
git -C $feature diff --stat origin/main...HEAD
git -C $feature push -u origin "feat/<작업명>"
```

추적 변경과 미추적 파일을 확인하지 않은 상태에서 PR을 올리지 않는다. 미추적
파일이 PR에 포함되어야 한다면 먼저 의도적으로 `git add`하고 commit한다.

## PR merge 후 처리

merge된 feature 브랜치는 다음 작업에 재사용하지 않는다.

```powershell
$main = "C:\Users\Playdata\Desktop\김동석\최종프로젝트\mle-01-final-team3-main"
$oldLfsSkip = $env:GIT_LFS_SKIP_SMUDGE
try {
    $env:GIT_LFS_SKIP_SMUDGE = "1"
    git -C $main fetch origin --prune
    if ($LASTEXITCODE -ne 0) { throw "origin fetch failed" }
    git -C $main pull --ff-only
    if ($LASTEXITCODE -ne 0) { throw "main pull failed" }
}
finally {
    if ($null -eq $oldLfsSkip) { Remove-Item Env:GIT_LFS_SKIP_SMUDGE -ErrorAction SilentlyContinue }
    else { $env:GIT_LFS_SKIP_SMUDGE = $oldLfsSkip }
}
```

다음 작업은 항상 최신 `origin/main`에서 새 feature worktree와 브랜치로
시작한다. 기존 merge 브랜치에서 다시 `git pull`하거나 `main`을 checkout하지
않는다.

작업 worktree를 정리할 때는 먼저 변경 상태를 확인한다.

```powershell
git -C $feature status --short
$ignored = @(git -C $feature status --porcelain=v1 --ignored --untracked-files=all | Where-Object { $_ -like "!! *" })
if ($ignored.Count -gt 0) {
    $ignored | ForEach-Object { Write-Output "Ignored file remains: $_" }
    throw "Do not remove the feature worktree until ignored files are secured."
}
git -C $main worktree remove $feature
if ($LASTEXITCODE -ne 0) { throw "feature worktree removal failed" }
git -C $main branch -d "feat/<작업명>"
if ($LASTEXITCODE -ne 0) { throw "feature branch removal failed" }
```

`status`에 변경이 남아 있으면 정리 명령을 실행하지 말고, commit 또는 별도
백업 후 다시 확인한다.

## Git LFS 처리

코드와 branch reference를 동기화할 때는 LFS 본문 다운로드를 자동으로 묶지
않는다.

```powershell
$oldLfsSkip = $env:GIT_LFS_SKIP_SMUDGE
try {
    $env:GIT_LFS_SKIP_SMUDGE = "1"
    git -C $feature pull --ff-only
    if ($LASTEXITCODE -ne 0) { throw "feature pull failed" }
    git -C $feature lfs status
}
finally {
    if ($null -eq $oldLfsSkip) { Remove-Item Env:GIT_LFS_SKIP_SMUDGE -ErrorAction SilentlyContinue }
    else { $env:GIT_LFS_SKIP_SMUDGE = $oldLfsSkip }
}
```

실행 환경에 필요한 LFS 본문이 없을 때만 별도로 준비한다.

```powershell
git -C $feature lfs pull
if ($LASTEXITCODE -ne 0) { throw "LFS pull failed" }
git -C $feature lfs checkout
if ($LASTEXITCODE -ne 0) { throw "LFS checkout failed" }
git -C $feature lfs ls-files
git -C $feature lfs status
```

`git pull`이 성공했다는 사실과 LFS 본문이 준비됐다는 사실은 별도로 확인한다.
`git lfs ls-files` 출력에서 필요한 파일이 `*`로 표시되어야 실제 본문이 준비된
것이다. `-`로 표시되면 포인터만 있는 상태이므로 데이터 준비를 완료로 판단하지
않는다.

## 미추적 파일과 충돌이 발생한 경우

- `git status --short --untracked-files=all`로 목록을 먼저 확인한다.
- `git reset --hard`, `git clean -fdx`, 강제 checkout으로 해결하지 않는다.
- 원격 checkout 대상과 같은 경로의 미추적 파일은 저장소 밖의 명시적인 백업
  폴더로 이동한 뒤 pull한다.
- pull 후 원격 파일과 내용이 다르면 백업본을 유지하고 수동 비교한다.
- `.env`, `.env.local` 및 인증정보는 자동 이동·출력 대상에서 제외한다.

## 최종 확인

```powershell
git worktree list
git -C $main status --short --branch
git -C $feature status --short --branch
git -C $feature lfs ls-files
git -C $feature lfs status
```

`main`과 feature worktree가 각각 의도한 브랜치를 가리키고, 추적 변경이 없으며,
LFS 상태가 별도로 확인된 경우에만 다음 작업을 시작한다.
